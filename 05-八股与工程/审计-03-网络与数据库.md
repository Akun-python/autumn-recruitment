# 审计报告：计算机网络 / 数据库笔记「小白友好度」评估

> 审计对象：`05-八股与工程/03-计算机网络.ipynb`（12 章 + 扩展专题 §12.1–12.16）与 `05-八股与工程/04-数据库.ipynb`（§1–§35，含两处 §10 重复编号），以及同名 `.md` 速查版。
> 审计方法：逐 cell 通读两个 notebook 的全部 markdown 章节（含目录、核心概念、正文、追问、易错点、扩展专题），并全文比对两个 `.md` 文件。
> 评价标准（每个概念三要素）：
> - **定义**：是否给出该概念是什么 / 做什么
> - **类比**：是否有生活化类比或直觉化比喻
> - **示例**：是否有可跟随的逐步例子（时序图、SQL 正反例、伪代码、Python 模拟、ASCII 图均算）
> - 完整度：**完整**（三者齐备）／**部分**（有定义+示例，缺类比或关键展开）／**缺失**（无定义即使用）

---

## 0. 总体结论

1. **整体定位是"面试背诵手册"而非"零基础教材"**：几乎每章都有定义、对比表、追问与易错点，示例密度很高（ASCII 图、SQL 正反例、Python 模拟、伪代码），"面试向"完成度优秀。
2. **"定义 + 示例"普遍齐备，"通俗类比"全线稀缺**：按三要素严格打分，两本书 47 个章节中没有任何一章做到"每个概念三要素齐备"；绝大多数章节为"部分"（定义 ✅ + 示例 ✅ + 类比 ❌）。真正算得上"完整"级别的只有零星概念：数据库 §1.1「索引 = 书的目录」＋成本伪代码、网络 §8.2「队头阻塞」的逐步拆解、数据库 §27「窗口函数 vs GROUP BY 的一句话区别」＋排名示例。
3. **最薄弱的三个地带**（对小白最不友好）：
   - 网络 §4.2 RTO/SRTT/RTTVAR 公式——公式直接砸脸，无任何直觉解释；
   - 数据库 §7.3 MVCC ReadView 可见性判断——术语链互相定义，无类比无时间线图；
   - 数据库 §5.2–5.3 物理日志 vs 逻辑日志（redo 的"页偏移" vs binlog 的"SQL/行映像"）——用黑话解释黑话。
4. **md 速查版是"截断版"**：网络 md 整段丢失 notebook 的 §12 扩展专题（粘包拆包、MSS/MTU 定义、连接队列、证书链 6 步、DNS 记录、排查工具等全在其中）；数据库 md 丢失范式、InnoDB vs MyISAM、连接池、半同步复制、快照读"经典事故"示例、SQL 注入攻击载荷全文等关键解释。具体见第 6 节。

## 3. TOP 10 最需补充「小白解释」的概念

> 摘录句均来自原文，按"新手第一遍读到必然卡住"排序。

1. **MVCC ReadView 可见性判断**（04-数据库 §7.3）
   > "if trx_id >= read_view.max_trx_id: return False # 快照之后才开始的事务，不可见"
   四个字段（m_ids/min/max/creator_trx_id）互相用"事务 id"解释彼此，"快照"无类比，规则纯背诵且易背反（作者自己标注了易错点）。最需一条时间线故事＋生活类比（"你进图书馆那一瞬间，已上架的书都能读，正在印刷的读不到"）。

2. **RTO / SRTT / RTTVAR 公式**（03-计算机网络 §4.2）
   > "SRTT = (1−α)×SRTT + α×RTT # α=1/8；RTO = SRTT + max(G, 4×RTTVAR)"
   公式直接砸脸：为什么加权平均、α=1/8 意味着什么、4×RTTVAR 的"4"是哪来的，全文无一句直觉解释。

3. **物理日志 vs 逻辑日志：redo / binlog / undo 的区别**（04-数据库 §5.2–5.3、§12）
   > "redo log（物理日志：记录'某个页的某个偏移改成什么值'）；binlog（逻辑日志：SQL/行映像）"
   "页偏移"和"SQL 映像"对小白都是黑话，三种日志的"记什么"没有记账本/胶卷类比，导致"为什么 redo 循环写、binlog 追加写"更无从理解。

4. **TLS 1.2 握手 8 步术语链**（03-计算机网络 §9.3）
   > "ClientKeyExchange：客户端交换自己的 ECDHE 参数，双方各自算出相同的预主密钥（pre-master secret）→ 用 client_random + server_random + pre-master 派生会话密钥"
   密码套件、椭圆曲线参数、pre-master、派生、ChangeCipherSpec、MAC 摘要、Finished 七个黑话在 8 步内连发，无一个展开；"非对称加密公钥/私钥"也没有邮箱/锁类比打底。

5. **幂等 / 安全方法**（03-计算机网络 §7.2）
   > "GET（安全、幂等、可缓存）；POST（非幂等）"
   全篇唯一出现"幂等"的地方就是这个表格，既无定义也无例子（"同样请求发 100 次结果应该相同"这一句都没给）；CORS 预检同样裸出现。

6. **快恢复 cwnd = ssthresh + 3**（03-计算机网络 §5.2）
   > "收到 3 个冗余 ACK 时 ssthresh = cwnd / 2，cwnd = ssthresh + 3"
   "+3"没有任何解释（对应 3 个已确认在途段＋收到 3 个冗余 ACK 的直觉），读者只能死背；速记表还把它当考点列出来。

7. **死锁四个必要条件**（04-数据库 §8.3）
   > "请求与保持：已持有资源，又去请求他人资源；不可剥夺：已获得的资源不能强行抢走"
   四条是操作系统教材原话搬运，"互斥/请求与保持/不可剥夺/循环等待"四个名词互相之间无生活例子（两人各持一把钥匙互等对方那把就是现成类比），小白只能望文生义。

8. **参数化查询 / 预编译为什么能防注入**（04-数据库 §34、md 版）
   > "参数化查询/预编译（首选）：占位符 ?，输入只当数据不当 SQL"
   "输入只当数据"结论给了，但"预编译"是什么、为什么占位符后输入就变不成 SQL（先编译骨架、参数走数据通道）缺一步机制拆解——这是小白最经典的疑问点。

9. **TCP 字节流 vs UDP 数据报（粘包根因）**（03-计算机网络 §6.5 易错点 / §12.4）
   > "TCP 是字节流无报文边界，UDP 是数据报有边界——『TCP 粘包问题』正源于此"
   "字节流/报文边界"用词互相解释；水管（连在一起的水）vs 邮包（每个包裹独立）的类比缺失，而粘包解释只在 §12.4（md 版还删掉了它，见第 5 节）。

10. **范式 2NF / 3NF**（04-数据库 §17）
    > "2NF：满足 1NF 且非主属性完全依赖主键；3NF：满足 2NF 且无传递依赖"
    表格虽有"通俗理解"列，但"完全依赖/传递依赖"仍是术语链；例题只有"省依赖城市"半个例子，没有"订单表 (订单号, 商品名, 商品价)"式的一步步拆解。
